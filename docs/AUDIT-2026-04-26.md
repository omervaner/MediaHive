# MediaHive Audit — 2026-04-26

Scope: `main.js`, `preload.js`, `main/`, `src/services/`, `src/components/`. Findings below
were verified by reading the code and probing call chains. Each entry cites exact file:line
locations. Severity tags: **CRITICAL** (runtime error / data loss), **HIGH** (user-visible
incorrect behaviour), **MEDIUM** (inconsistency / minor incorrect behaviour),
**LOW** (cosmetic / dead code / noise).

---

## 1. Bugs

### 1.1 `setIsLoadingFolder` is not in scope — Escape-during-load throws — **CRITICAL**
`src/App.jsx:1456-1462`

```js
useEffect(() => {
  const onKey = (e) => {
    if (e.key === "Escape" && isLoadingFolder) setIsLoadingFolder(false);
  };
  document.addEventListener("keydown", onKey);
  …
}, [isLoadingFolder]);
```

`isLoadingFolder` is destructured from `useElectronFolderLifecycle()`
(`src/App.jsx:304`), but the hook **does not export** `setIsLoadingFolder`
(`src/app/hooks/useElectronFolderLifecycle.js:378` exports only the value).

Result: pressing Escape while a folder is loading throws
`ReferenceError: setIsLoadingFolder is not defined`. The error is unhandled, so
the keydown listener will reject and React/Electron will log a thrown error.
Either expose the setter from the hook or call a hook-provided cancel method.

### 1.2 `move-to-trash` IPC handler calls undefined `trash()` — **CRITICAL (dead path, but trips ReferenceError if reached)**
`main.js:1826-1834`

```js
ipcMain.handle("move-to-trash", async (_event, filePath) => {
  try {
    await trash([filePath]); // batch of size 1
    return { success: true };
…
```

`trash` is **never imported** in `main.js` (the `trash` package appears in
`package.json` deps but no `require("trash")` anywhere). The whole trash flow
is registered separately at `main/ipc-trash.js` (using `shell.trashItem`). The
renderer wires the API as `electronAPI.moveToTrash` (`preload.js:168`), but
checking grep, all live callers actually use `bulkMoveToTrash` instead
(`src/App.jsx:1366`, `src/hooks/actions/actions.js:108,123`).
`ContextMenu.jsx:57` only references `electronAPI.moveToTrash` for a truthiness
check. So this handler is dead — but if anything ever invokes it, it will throw
`ReferenceError: trash is not defined`. Delete the handler and the preload
wrapper.

### 1.3 Single-image AI caption is never persisted to DB — **HIGH (data loss)**
`src/components/MetadataPanel.jsx:289-344` calls `electronAPI.caption.both(...)`
and updates `captionState` in component state, but **never** calls
`electronAPI.metadata.setCaption(...)` afterwards. The IPC for persistence
exists (`preload.js:232`, `main.js:1785-1807`) but is unused renderer-side
(grep `setCaption|metadata:set-caption` in `src/` returns only React state
setters, not the IPC).

Behaviour: user picks a single image, clicks "Generate caption", waits, sees
the caption — closes the panel or selects another item, comes back, caption is
gone. Compare with `main.js:2095-2128` where the **batch** flow saves via
`store.setCaption(...)` inside the progress callback. The single-image path
needs the same persistence step (renderer or main side).

### 1.4 `generateCaptionAndTags` cancellation is wired to a controller no fetch is using — **HIGH**
`main/captionService.js:232-276`

```js
const controller = new AbortController();
if (requestId) activeRequests.set(requestId, controller); // ← never connected
…
const captionResult = await generateCaption(imagePath, { ...options, requestId: null });
…
const tagsResult = await generateTags(imagePath, { ...options, requestId: null });
```

The combined helper builds its own `AbortController`, registers it in
`activeRequests`, but passes `requestId: null` to the inner calls so the inner
fetches each create their own `AbortController` whose signals are unrelated.
`cancelRequest(requestId)` aborts the wrapper controller, but neither inner
`fetch` listens to it. Cancellation only takes effect at the **boundary
between** `generateCaption` and `generateTags` (line 248: `if
(controller.signal.aborted)` check). A user pressing Cancel while the model is
mid-inference cannot stop the in-flight request.

Also the per-call `timeoutMs` from `getTimeoutForModel` is applied
independently in each inner call, so the combined operation effectively gets
**2× the configured timeout**.

### 1.5 Dataset export writes empty `.txt` files — **HIGH (matches user-reported symptom)**
`main/datasetExporter.js:92-109`

```js
if (includeCaptions) {
  const captionPath = destPath.replace(/\.[^.]+$/, ".txt");
  let captionContent = "";

  if (captionSource === "ai" && file.aiCaption) {
    captionContent = file.aiCaption;
  } else if (captionSource === "tags" && Array.isArray(file.tags) && file.tags.length > 0) {
    captionContent = file.tags.join(", ");
  } else if (captionSource === "ai" && Array.isArray(file.tags) && file.tags.length > 0) {
    captionContent = file.tags.join(", ");
  }

  await fs.promises.writeFile(captionPath, captionContent, "utf-8");
}
```

When neither `aiCaption` nor `tags` are present, `captionContent` stays `""`
and an empty `.txt` is still written. Two follow-on issues:

- The third branch (`captionSource === "ai"` fallback to tags) is
  unreachable — it duplicates the second branch's filter and is gated on `===
  "ai"`, but the prior branch only fires when `captionSource === "tags"`. The
  intent (in the UI hint at `ExportDialog.jsx:253-255`: "AI captions falls
  back to tags if no caption") is broken: when AI is selected and no
  `aiCaption`, the second branch is skipped (because `captionSource !== "tags"`)
  and the third branch is skipped (because the second already returned `""`)…
  actually trace it carefully: the chain is `if/else if/else if`, so when
  `captionSource === "ai" && !file.aiCaption`, control falls to the second
  branch (`captionSource === "tags"` — false), then the third
  (`captionSource === "ai" && tags…` — true if tags exist). So the fallback
  *does* work. But `captionSource === "tags"` has **no fallback to AI caption**,
  which is the asymmetric/inconsistent half.
- For `captionSource === "tags"` with no tags, we still write `""`.

Fix: skip the write when `captionContent === ""`, and decide on a symmetric
fallback policy (or document the asymmetry).

### 1.6 Legacy settings migration silently fails — uses callback fs as if promise fs — **HIGH**
`main.js:540-554`

```js
const legacyRaw = await fsPromises.readFile(legacyPath, "utf8");
…
await fs.mkdir(path.dirname(targetPath), { recursive: true });
await fs.writeFile(targetPath, JSON.stringify(toPersist, null, 2));
```

Lines 15-16 import `const fs = require("fs")` and `const fsPromises =
fs.promises`. The two `await fs.…` calls on lines 545-546 invoke the
**callback** API without a callback. In modern Node that throws
`TypeError: callback must be a function` synchronously — caught by the
surrounding `try/catch` (line 549-553) and logged as a warning, but the
migration never happens. Anyone with a pre-profile-system `settings.json`
in the userData root never gets it migrated. Replace `fs.mkdir` /
`fs.writeFile` with `fsPromises.mkdir` / `fsPromises.writeFile`.

### 1.7 Move dialog reports failed moves as moved — **MEDIUM (data-view drift)**
`src/components/MoveDialog.jsx:134-141` calls
`onComplete({ movedFiles: files.map(f => f.fullPath), … })` whenever
`res.success && mode === "move"`, regardless of whether `res.errors.length >
0`. App.jsx (`src/App.jsx:1657-1665`) then prunes those paths from the videos
list. Files that failed to move are still on disk but vanish from the UI
until reload.

Use `res.movedFiles` from the backend, or filter by absence in `res.errors`,
before telling App.jsx what was actually moved.

### 1.8 `BatchCaptionDialog` skip-existing rule conflates manual tags with AI tags — **MEDIUM**
`src/components/BatchCaptionDialog.jsx:113-130`

```js
if (options.generateCaptions && options.generateTags) {
  return !f.aiCaption && !f.tags?.length;        // skip if either AI caption or any manual tag exists
} else if (options.generateCaptions) {
  return !f.aiCaption;
} else if (options.generateTags) {
  return !f.tags?.length;                         // skip if any manual tag exists
}
```

Files with manually applied tags (and no AI run) get skipped even when
"Generate tags" is requested, because manual tags and AI tags share the same
field after batch save. The check that "avoids redoing work" should be against
`aiTags`/`aiCaption` (or against a "captioned-by" marker), not against the
manual tag list. Otherwise users who tagged a few files by hand can't get AI
tags on those files without ticking "Overwrite existing".

### 1.9 In-memory image-dimension cache grows unbounded — **LOW**
`main/imageDimensions.js:4` declares `const CACHE = new Map();` keyed by
`path::size::mtime`. Entries are never evicted. For long-lived sessions over
large galleries this is a real (if slow) leak. `main/videoDimensions.js`
should be checked for the same pattern. Add an LRU cap (e.g. 5k entries).

### 1.10 `useVideoStallWatchdog` is named like a hook but isn't — **LOW (rules-of-hooks confusion)**
`src/hooks/useVideoStallWatchdog.js:36` exports `useVideoStallWatchdog` with
the `use*` prefix, but it does not call any React hooks; it just registers a
subscriber and returns a teardown. `VideoCard.jsx:319` calls it from inside a
`useEffect` — which is illegal for actual hooks, but works here because the
function isn't a hook. The naming will trip ESLint's `react-hooks/rules-of-
hooks` and confuses readers. Rename to `subscribeVideoStallWatchdog` or move
the call back to top level with an `enabled` flag.

### 1.11 `errorText` set on image errors is never displayed — **LOW (dead state)**
`src/components/VideoCard/VideoCard.jsx:868-870` does
`setErrorText("Failed to load image")` from the `ImageElement` `onError`
callback, but the JSX branch (line 855) always renders `<ImageElement>` for
images and never falls through to `renderPlaceholder()` (which is the only
consumer of `errorText`). The image error is actually shown by
`ImageElement`'s own internal `error` state (line 56-63), so the user does see
something, but the parent's `errorText` is dead. Drop the `setErrorText` from
the image branch.

### 1.12 `onSettingsLoaded` never returns an unsubscribe — **LOW**
`preload.js:123-127` is the only `electronAPI.on*` listener that doesn't
return a cleanup function. Every other listener does. Renderer code that
mounts/unmounts (e.g. dialogs) cannot detach this listener, accumulating one
handler per remount. Currently the only caller is the top-level App which
never unmounts, so the leak is theoretical — but still inconsistent.

### 1.13 Find Duplicates always reports zero — caller invokes `duplicates:find` per-file — **HIGH (feature is non-functional)**
Found while smoke-testing the `main/ipc-duplicates.js` extraction. The IPC
handler itself is correct: given a list of fingerprints, it ensures each has
a phash and runs `findDuplicateGroups` with threshold 5. But the renderer
fires `duplicates:find` **once per file with a single-element fingerprint
array** instead of one batched call for the whole folder, so each invocation
operates on a 1-item set and `findDuplicateGroups` can never form a group.

Reproduction: load three byte-identical screenshots, click "Find Duplicates",
observe in the main-process log:

```
[duplicates] Computing hashes for 1 of 1 files
[duplicates] Found 0 duplicate groups
[duplicates] Computing hashes for 0 of 1 files
[duplicates] Found 0 duplicate groups
…
```

Five calls fire, each handed one fingerprint. UI shows "No duplicates found".
Fix the caller (search `App.jsx` / hooks for the `duplicates:find` invocation)
to send the full fingerprint array in one call. The handler does not need to
change.

This supersedes the §7 "duplicate-finder happy path" entry — that entry
probed only the IPC handler, which is correct; the bug is in the caller.

simplification — but `CLAUDE.md` should be updated so the doc matches the
shipped surface, otherwise future-you will look for a handler that doesn't

## 6. Smaller things worth a sweep

- `src/components/ExportDialog.jsx:308` rename preview hardcodes `.jpg` —
  doesn't reflect the actual source extension. Cosmetic.
- `main/datasetExporter.js:86` — `await fs.promises.rename(sourcePath,
  destPath)` will fail with `EXDEV` if the destination is on a different
  volume. Worth wrapping with a copy+unlink fallback for the move path.
- `main/datasetExporter.js` — when `rename` is null and two source files
  share a basename (different folders, recursive scan), `destPath` collides.
  `copyFile` silently overwrites, `rename` errors. Add a name-uniqueness pass
  or warn in UI.
- `src/services/thumbService.js:115-187` — `drawRoundedThumbnail` is video-
  centric; the overlay-triangle "play button" is drawn into every captured
  thumbnail. Fine as-is because thumbs are only captured for videos
  (line 226 returns when `videoElement.paused`), but the function is named
  `drawRoundedThumbnail`, not `drawVideoThumbnail` — slight misnomer.
- `src/components/HeaderBar.jsx:393` — Export button is disabled when
  `imageCount === 0`. The dataset exporter itself is image-only (it uses
  `sharp` for resize), so this is correct, but the title attribute "No images
  to export" is the only signal users get. A tooltip or menu hint that
  "exporting only operates on images" would help.
- `main/perceptualHash.js:findDuplicateGroups` is **O(n²)**. For folders of
  ~10k images this becomes noticeable. Not a bug, just a scaling note.
- The standalone top-level `AboutDialog.jsx` (menu) and the Settings sub-
  modal `AboutModal` (in `SettingsDialog.jsx`) duplicate the same concept
  with different copy and different brand strings. Either merge or keep one.

## 7. What is **not** broken (probed and ruled out)

- `src/app/filters/filtersUtils.js` filter math — `matchesResolution`,
  `matchesAspectRatio`, `matchesScreenshotFilter` all behave correctly,
  including the "no dimension data → don't filter out" defaults.
- Tag include/exclude logic in `FiltersPopover` — toggle-cycle works for both
  include and exclude, and switching modes correctly removes from the other
  set.
- The duplicate-finder **handler** itself: `duplicates:find` handles
  missing-`phash` rows (it computes them) and skips video files via
  extension whitelist. `findDuplicateGroups` filters items without a hash
  before grouping (`main/perceptualHash.js:87`). Note the **caller** is
  broken — see §1.13.
- `MetadataPanel` tag/rating updates correctly persist via
  `metadata:add-tags` / `metadata:set-rating`. Only the **AI caption**
  persistence is missing (see 1.3).
- The batch caption persistence path — `caption:batch`'s onProgress callback
  saves to DB via `store.setCaption` and `store.assignTags`
  (`main.js:2107-2117`).
